# Private motion delivery and calibration

Cigarette events and raw calibration recordings are separate. A cigarette can be counted locally before its raw wrist samples are available on the private dashboard. The shared dashboard is https://ciggy.thatcanadian.dev; each iPhone must be paired and explicitly sharing. Only samples at or after that consent boundary are eligible. No heart rate, cigarette notes, location, or upload credential travels from Watch in a motion recording.

## Build 9 delivery path

Raw calibration now uses the durable file lane only. The immediate multipart sender from build 8 is removed; its receiver remains compatible with older in-flight messages. The first raw file starts an hour-long waiting period, persisted across relaunches. At the next legitimate wake after the deadline, pending files become eligible together. At most two raw file transfers are outstanding; completions admit the next file in that batch. New files wait for the next hourly release. Missed wakes defer delivery rather than starting repeated catch-up timers. Updating from build 8 restages outstanding raw transfers once, preserving saved files. Ordinary cigarette events, settings, detection and counter sync do not use the calibration batch schedule.

Live capture keeps its five-minute / 3,000-sample buffer through ordinary history checks and cigarette candidates, saving at the cap or on background entry. Calibration queue-change status is debounced; Core Motion extraction releases Objective-C objects per window. The Watch queue is bounded to 80 MiB and 48 hours, clearing the oldest files first when either limit is reached. watchOS still decides when the app and its transfers run; an hourly target is not a guaranteed arrival time. The iPhone uploads received files over Wi-Fi.

The dashboard automatically loads compact summaries for every received recording in the selected period (past 48 hours by default). It fits the graph to all received data rather than the newest file, joins adjacent measured sequences, preserves five-second minima/maxima, breaks lines at gaps over one second, shows isolated samples as points, and deduplicates coverage across overlapping sources. Source and date filters are optional. Last motion, its age, last upload and partial-load progress are visible. Labels remain per recording; dragging selects the matching file automatically and discloses any clipped boundary.

Chart summaries are derived from immutable raw motion and saved with the private D1 recording row. Existing recordings are summarized on their first chart read and reused thereafter. They inherit source access controls, deletion and 14-day expiry. Metadata polling remains bounded at one minute (five-minute full reconciliation); new summaries arrive without resetting an unsaved label. Failed reads preserve received data and show a partial-chart state. Summaries are charts, not cigarette classifications or training results.

The physical launch crash was not reproduced in the Watch simulator. Device crash retrieval was blocked by the Watch developer tunnel and the connected iPhone's disabled Developer Mode. Build 9 reduces raw-transfer and extraction pressure; it does not claim a confirmed crash root cause.

## Historical build 8 delivery path

1. While the Watch app has live motion, an opt-in buffer retains real acceleration, orientation and gyroscope samples at up to 10 Hz. It flushes on a cigarette candidate, foreground refresh (normally each minute), and background entry; buffers also cap at five minutes / 3,000 samples. It does not run live sensors indefinitely while suspended.
2. Background accelerometer history remains a separate source with no gyroscope. Complete five-minute windows become eligible after the three-minute source-availability allowance. Usable fragments are now exported even when a window has a boundary gap, invalid point or missing interval. Gaps remain in the data; the source window stays pending for reconciliation. Unchanged fragments have stable IDs. Fuller replacements receive distinct immutable IDs, preserving existing samples and labels.
3. Source retries start after one minute and back off to fifteen minutes. Sensor clock jitter reaching the sample cap no longer discards an otherwise complete window. Calibration collection precedes older detection backlog during an available Watch wake. A received sharing setting requests a check immediately; watchOS still controls when an inactive app can run.
4. The Watch saves each file before queueing delivery. It always keeps the normal durable WatchConnectivity file lane. When reachable, it also attempts a bounded immediate lane: 40 KiB parts, two concurrent recordings, at most 2 MiB each, a 15-second attempt and 30-second retry spacing. Larger files use the durable lane. The phone checks the whole-file SHA-256 and recording schema, atomically saves the complete bytes, and only then acknowledges receipt. The Watch cancels the redundant file transfer only after that receipt. Multipart inboxes survive relaunch, retain at most eight pending recordings, and expire after 24 hours. Receipts handle late duplicate messages and the durable file winning the race.
5. The iPhone validates/imports the persisted recording and queues a non-discretionary background URLSession upload over Wi-Fi. Matching server receipts make uploads idempotent. Server reservations remain bounded at 8,192 per device over 72 hours, including deleted/reserved records; the former 576 limit could not sustain three days of five-minute history alone. Authentication, allowed reviewers, source-age limits and 14-day server retention are unchanged.
6. The open dashboard checks recent saved metadata each minute. It reuses older metadata between full reconciliations every five minutes and explicit Refresh; hidden tabs and unsaved labels pause polling. Date filters bound server reads, incomplete pages preserve loaded data, and large views ask for a narrower period. Raw samples are loaded on demand. Labels do not modify the cigarette counter or train a detector automatically.

## Diagnose an empty dashboard

In iPhone Settings → Private motion calibration, check Sharing, Last upload, pending recordings and the latest Watch status. Status distinguishes waiting for the Watch to receive consent, waiting for source history, and files queued on Watch. The displayed Watch-check time matters: it is a last report, not a guarantee that the Watch is awake now. **Check Watch and retry uploads** resends current settings, requests a bounded Watch check, resumes device sync and retries the phone queue. Keep the paired iPhone on Wi-Fi. Update both companion apps for hourly calibration batches. Retry requests a check and retries phone uploads; it does not bypass the Watch batch deadline.

Saved live fragments and extracted background history wait for the next hourly file batch. History windows also need roughly three to eight minutes for source availability before extraction, followed by Watch wake, device transfer and upload scheduling. The first whole post-consent window cannot be eligible before eight minutes. There is no guaranteed arrival time under watchOS/iOS suspension, loss of connectivity or force quit. Data from before consent is intentionally excluded. Local queues are bounded (80 MiB on Watch, up to 48 hours of source age), so offline storage is not unlimited. Saved shared recordings and labels expire after 14 days.

## Back-to-back cigarettes

The current detector still groups repeated gestures using the existing 150-second gap rule. This delivery update does not claim to distinguish every pair of back-to-back cigarettes. Mark each actual cigarette as a separate smoking interval, and number it in Notes; touching intervals can describe cigarettes with no pause. Use the recording-type filter to inspect live gyro-supported samples or acceleration-only history. Overlapping sources/fragments are evidence for the same time, not extra cigarettes. These labelled sequences are needed to evaluate motion-based transitions against one longer cigarette, eating and drinking before changing automatic counts.
