# Detection windows and private missed-cigarette feedback

Build 21 keeps the review's broad period and lists all original detections on both devices. Each row uses the saved `motionSessionStartedAt` and event `timestamp`: the beginning of the duration segment and the qualifying motion timestamp that produced the count. Historical analysis uses source timestamps, not the later processing or phone-arrival time. These are evidence windows, not verified smoking intervals. Missing legacy starts and missing event snapshots stay explicitly unavailable. Adjusted counts retain the original estimates without assigning fictional timestamps to corrections.

The iPhone's **Inspect motion & report a miss** opens the existing Cloudflare Access dashboard in `SFSafariViewController`. The user stays in Ciggy and returns with Done. Only validated review scope (`from`, `to`, optional participant UUID and review UUID) is passed; no upload credential, heart rate or personal event notes go to the browser. Safe same-origin login redirects retain that scope. An existing pairing can recover its own participant UUID through the bearer-authenticated `GET /api/participant`; all dashboard browsing and feedback still require Access. If identity is unavailable, the tester must choose a participant explicitly.

In the dashboard, select **Drag to report a missed cigarette**, zoom and drag across any interval, or use the exact local date/time fields in **Report a missed cigarette**. Reports can span multiple files or no files. The tester supplies the missed count, observation and optional notes. These reports neither modify app totals nor train the detector. Activity labels remain a separate, per-recording workflow.

Feedback is durably saved in D1 per authorized participant/workspace, with a client UUID for idempotent retries. It expires after 14 days, disappears immediately from reads at expiration, and is purged by the existing cleanup. Deletion clears its body and retains a temporary tombstone against delayed retries. Participant deletion also removes feedback. Validation bounds reports to a recent interval of at most 24 hours, 1–100 missed cigarettes, 2,000 note characters and 500 unexpired reports per participant. Writes require a same-origin Access session.

Each saved report can prepare an evidence file. The export reconciles the selected participant's exact interval, validates all metadata pages, and fails if a raw recording cannot load; it cannot silently turn a partial response into zero motion. The file contains tester-reported feedback (Unix milliseconds), timezone, source coverage and gaps, interval-clipped raw recordings and labels (the existing Apple 2001-second encoding), and the last reported delivery status. A second user action shares or downloads the file, preserving the mobile browser's user-gesture requirement. Only the selected participant is included.

Coverage describes uploaded calibration evidence at the time of inspection/export. An empty interval can reflect missing capture, delayed transfer, sharing being off or retention. It is not proof that the Watch was not tracking. Source filters affect the main chart; feedback evidence deliberately includes all motion sources for its chosen tester. Server data remains the durable source, overviews are reused, and explicit evidence export reads only the selected interval. Tester data and exported reports belong in the private workspace or a private debugging conversation, never in this public repository.
